## 现场观察记录

**2026-10-16**(G1~G8 版在跑,默认 Kp=1.8/Ki=0.30,bPidTune=OFF):设定 100mm,水位升到 ~110mm 泵才启动,抽到 ~95mm 才停,±10mm 极限环。诊断:积分振荡——下降段误差为负把积分拉深,回升段 P 项要先填平负积分坑才够 3% 开泵阈值;过冲段正积分又撑着阀关不掉。Ki=0.30 对慢积分对象过大,且旧 ±100 原始积分钳位使 I 项摆幅达 ±30% 阀开度。处置:[G9] 积分改贡献量限幅 + 默认 Ki 降至 0.10;临时在线缓解 `set-pid 2.0 0.10 0`;根因裁定仍靠 `step_test.py` 实测 K/τ。

另有细节:首周期(`bFirstScan`)用实测值初始化滤波器/斜坡/限速基准,避免上电从 0 拉起造成假误差冲击;手动模式下同步 `rPrevValve`/`rPrevLevel`,保证切回自动无扰。

**2026-10-19**(G1~G12 在跑,自学习 `bAutoLearn=TRUE`,Kp=2.0/Ki=0.10)

自学习回读(`output/get_learn.txt`):

- **d0 学习正常**:`0.2778 → 0.4605 → 0.4564 → 0.4766 → 0.4708 %/s`,即收敛到 **≈0.46~0.48 %/s**。过程可解释:`set-mm 50` 把阀拉满排水,再 `set-mm 100` 时液位远低于目标 → 阀饱和在 0 → 长时间"阀全关自由上涨"→ 门控打开,`rRateFilt` 稳定后就是真 d0。
- **u_eq 恒读 22.96%**:不是坏了。默认值 20.0 已被推到 22.96,正落在自动模式阀指令摆动的中间(现场 status 日志里阀 15.8~26.3%),即**已经收敛**;EMA 收敛后单拍变化 <0.005%,而旧版 `get-learn` 只显示两位小数,所以看起来"冻结"。现已把显示改到 4 位并顺手输出 `K = d0/u_eq`(本例 ≈0.0205 %/s per %阀)。

阶跃试验(`output/step_test_ABORTED_20261019_163025.csv`,77 行,中止):

- **中止原因**:u0 取的是自动模式的**瞬时**阀指令 33.51%,比真实平衡开度(≈23%)高约 10% → 整个基线在排水,液位从 103mm 一路掉到 73mm(-0.46 mm/s),阶跃 +10% 后 10 秒内跌到 43.49mm,触发 45mm 守卫 → 手动模式无 PLC 联锁,工具自守卫按设计动作,阀已回 u0、模式已还原。
- **抢救出的数据**(切线法):s0=−0.314 %/s,s1=−2.24 %/s,**K≈0.19 %/s per %阀,τ≈2.4 s**,外推 **d0≈+6.15 %/s**。
- **但这个 K 不能用**:外推 d0=6.15 与实测学到的 0.47 差 **13 倍**;而用学到的 d0/u_eq 反推的工作带增益 K≈0.021 能同时解释基线斜率(0.47−0.021×33.5≈−0.23,实测 −0.31)。也就是说 **阀从 33.5% 开大到 43.5% 后排水速率从 0.5 加速到 2.9 mm/s,这一段落在低液位(43~73mm)强非线性区**,斜率差被"液位自己也在跌"污染了。结论:本次只给出 τ 的量级(1~3 s,响应在阶跃后 1~2 s 内就跟上了,纯滞后确实很小),**K 必须在平衡点附近重测**——K 差 9 倍,SIMC 推荐增益就差 9 倍,不能据此加大 Kp/Ki。

工具改造(`step_test.py`,针对上面两个坑):

1. **u0 默认改取 PLC 学到的 u_eq**(与 `get-learn` 同一寄存器来源),读不到才退回当前阀指令;
2. 新增**调零探针**:切手动后先测 20s 斜率,若液位还在漂就按 `Δu = s/K_prior` 微调 u0(最多 3 次,单次 ≤15%),直到基线接近静止才开始记录——保证样本取自平衡点附近;
3. **记录时长按离守卫的液位余量自动截短**(余量 / 预估速率 × 0.8),不再固定 180s 把水箱排到底;
4. **中止/中断也用已采数据输出分析**,并对"基线漂移 >15mm""阶跃后漂移 >25mm""外推 d0 与学到的差 >2 倍"给出有效性警告;
5. `--record` 默认 120s,新增 `--probe` / `--no-trim`。

下一步:在 100mm 附近重跑 `python3 step_test.py`(现在会自动从 u_eq≈23% 起步并调零),取干净的 K 与 τ。

**2026-10-20**(`output/step_test_20261020_102234.csv`,245 行,完整跑通)

调零后 u0=20.8% 记录 60s → 阶跃 +10% 到 30.8% → 记录 ~180s。结果:

| 量 | 实测值 |
|---|---|
| 基线斜率 s0 | +0.053 %/s(调零生效,基线基本静止)|
| 阶跃后斜率 | 前段 −0.527 → 末段 **+0.019 %/s(归零)** |
| 液位 | 79.51% → **58.19% 后走平**(103.2 mm)|
| 对象模型 | **自衡一阶 + 纯滞后(FOPDT)**,不是积分对象 |
| 静态增益 K | **−2.132 %液位 / %阀** |
| 时间常数 τp | **18.6 s**(两点法 28.3%/63.2%)|
| 纯滞后 θ | **5.0 s** |
| 平衡线截距 C | **58.06%**(阶跃前后两点各解一次,相差 <0.01%)|

三条结论:

1. **阀固定后液位趋于新平台 ⇒ 对象自衡。** 之前所有推导都建立在"积分对象"(阀全关=恒定速率上涨)上,这次数据直接否证:把自衡对象按积分模型辨识,分母斜率差趋于 0 → K 趋于 0 → 推荐增益爆炸(上一版吐出 `Kp=107`,就是这么来的,已加判型与可信度拒绝)。
2. **SIMC(FOPDT)推荐**:λ=θ → Kp 0.88 / Ki 0.047;λ=2θ(鲁棒)→ **Kp 0.58 / Ki 0.031**;λ=3θ → 0.44/0.024。而昨天那次被判废的 IPDT 数据按切线法算出的 Kp≈0.9/Ki≈0.045 **与今天的标准档撞在一起**(K·τ 乘积相近,两条路殊途同归)——两次独立试验都把增益指在 **Kp≈0.6~0.9、Ki≈0.02~0.05**。现在在跑的 Kp=2.0/Ki=0.10 高了 2~3 倍,这正是残余 ±3.5mm 缓慢摆动的原因。
3. **`u_eq` 随目标水位线性变化**:平衡线 `u_eq(h) = C − h/2.132`。昨天学到的 u_eq=22.96(目标 100mm)与今天解出的 u_eq(100mm)≈31 对不上,差在 **C**:昨天 C≈49.1,今天 C≈58.1 ——两桶水量分配变了(左桶加水)。所以 [G12] 该学的是 **C**(装水量的指纹),不是 u_eq;这正好落实了此前"左桶水位一变参数就漂"的担忧,并且解释了为什么必须持续在线学,不能手测写死。

工具改造(`step_test.py`):自动判型(末段斜率归零→FOPDT,仍在漂→IPDT),FOPDT 走两点法 + SIMC 三档;新增可信度拒绝(鲁棒档 Kp>10 或 Ki>1 直接判"本次辨识不可用");有有效性警告时不再打印"现场应用"命令;报告新增平衡线截距 C;`u0` 换算改为"PLC u_eq + (SP−当前液位)/K"(即当前液位的平衡开度)。`water_control_cli.py get-learn` 改为输出 d0 / 按目标派生的 u_eq / 推算的 C 与自由上涨天花板,并提示当前阀开度相对平衡开度是偏大还是偏小。

## 增益裁定:阶跃试验(`step_test.py`)

两套文档增益(3.0/0.45 vs 1.8/0.30)矛盾且出处不可考,**以实测为准**。**2026-10-20 实测裁定:本对象是自衡一阶 + 纯滞后(FOPDT),不是积分对象** —— 阀开度固定后液位会趋于一个新平台(实测 79.5%→58.2% 后走平)。辨识参数为 K=−2.13 %液位/%阀、τp=18.6 s、θ=5.0 s,对应 SIMC:**Kp 0.88 / Ki 0.047(λ=θ)**、**Kp 0.58 / Ki 0.031(λ=2θ,鲁棒)**;当前在跑的 2.0/0.10 偏高 2~3 倍。

⚠️ 判型错误会直接毁掉推荐值:把自衡对象按积分模型辨识,斜率差趋于 0 → K 趋于 0 → 推荐增益爆炸(实盘吐过 `Kp=107`)。工具现已自动判型,并在鲁棒档 Kp>10 / Ki>1 时拒绝给出应用命令。

`skill/water-level-control/scripts/step_test.py` 用经典反应曲线法自动完成:

```bash
# 液位先调到试验窗口 (55-140mm, 建议 90-100mm), 然后:
python3 step_test.py                 # 默认: 阀+10%阶跃, 基线60s+记录180s
python3 step_test.py --step -10      # 液位偏高时用关小阀方向
```

流程:切手动→开泵→阀置 u0(取 PLC 学到的 u_eq 按**当前液位**换算的平衡开度)→调零探针→记录基线→阶跃 Δu→记录响应→恢复现场→输出:

- **自动判型**:阶跃后末段斜率归零且走过足够距离 → **自衡(FOPDT)**;仍在等速漂移 → **积分(IPDT)**
- **FOPDT 分支**:静态增益 K(Δ液位平台/Δu)、τp 与 θ(两点法 28.3%/63.2%)、**平衡线截距 C**(两个平台点各解一次并比对,相差小 = 线性关系成立),SIMC `Kp = τp/(|K|(λ+θ))`、`Ti = min(τp, 4(λ+θ))`,输出 λ=θ / 2θ / 3θ 三档
- **IPDT 分支**(仅当对象真的无平台):K =(s0−s1)/Δu、τ(切线法)、d0(阀全关时自然入流速率),SIMC `Kp = 1/(K(λ+τ))`、`Ti = 4(λ+τ)`,输出 λ=τ / 2τ 两档
- **可信度闸门**:鲁棒档 Kp>10 或 Ki>1 → 判"本次辨识不可用",不打印应用命令;有有效性警告时同样降级为"仅量级参考"
- 原始数据 CSV(时间/液位mm/液位%/阀开度/状态字),可复查拟合;中止/Ctrl+C 也用已采数据出报告

拿到推荐值后的落地顺序:

1. `water_control_cli.py set-pid <Kp> <Ki> 0` 在线写入(bPidTune 路径,无需重新下载程序),再用 `set-mm` 设几个不同目标观察(写完用 `read-mm`/`status` 轮询);
2. 确认稳定后回填三处:`st/PLC_PRG_improved.st` 声明区默认值(G1)、若不同水位段实测出差异(多个液位高度重复试验取点),分档表已随之删除,需要在 PLC 侧加分段;`SKILL.md` 文档;
3. 在 Machine Expert 中重新编译下载,使 bPidTune=0 时的默认值也是实测值。

**安全说明**:手动模式下 PLC 的 HH/LL 联锁被手动阀开度覆盖(ST 第 5 段在联锁之后执行),试验期间 PLC 不提供液位保护——工具自带守卫:液位越出 [45,150]mm、传感器故障或 Ctrl+C 均立即中止并把阀恢复到 u0、按试验前模式还原。

## 参数标定:预开阀要什么数([G11]+[G13])

**默认 `bPreOpenEn = FALSE`(不生效)。** 新版预开律只需要两个数,而且都不是"手测三个数"那种:

| 参数 | 来源 | 现值 |
|---|---|---|
| `rStatK` | 静态增益 \|K\|,**`step_test.py` 实测一次**(慢变量,只跟管路与阀特性有关) | 2.13 %液位/%阀(2026-10-20)|
| `rUeqBase` | 平衡线截距 C,**[G12] 在线自学习**(快变量,跟两桶装水量走) | 默认 58.0,实测 58.06 |

`d0`(`rInflowRate`)现在只是**诊断量**(阀全关时的上涨速率),预开律不再用它算提前时间 —— 自衡对象里"到达目标的时间"这个概念本身就不需要:把阀开到 `u_eq(SP)`,对象的平衡液位就是 SP,液位自己会减速停住。

### 为什么 C 而不是 u_eq

平衡线 `u_eq(h) = C − h/rStatK` 是实测解出来的:今天两个平台点 (u=20.8%, h=79.5%) 与 (u=30.8%, h=58.2%) 各自解出的 C 相差 **<0.01%** —— 线性关系在本段量程内成立。C 在同一装水量下与水位无关,所以**换一个目标不用重学**;而 u_eq 随目标线性变(100mm 需 ~31%,130mm 只需 ~21%),把它当常数学就会在换目标后偏约 10% 阀开度。

### 装水量变化怎么办(左桶加水)

C 会整体平移:2026-10-19 反推 C≈49.1 → 2026-10-20 实测 C≈58.1(左桶加水,自流平衡水位随之抬高,`get-learn` 里的"自流平衡点(模型外推)"= C×rStatK 从约 105% 抬到约 124%,已超出量程,即靠自流可以一直涨到顶)。这正是之前担心"左桶水量一变参数就漂"的那个量,现在:

- **在线跟随**:每个稳态点都在学 C(60s 时间常数),不需要人工重标定;
- **可观测**:`get-learn` 直接打印推算出的 C 与自由上涨天花板,C 明显偏离上一次的值 = 装水量变了;
- **仍然建议左桶水位固定**(标一条水位线,或加溢流堰做恒压头):C 稳定时预开律最准,自学习只是在补漂移。

**需要重测 `rStatK` 的情况**:改动上管路(管径、长度、阀门)、换泵换阀 —— 这时静态增益才变。仅装水量变化不用重测。

### 手测校核(可选,用来验证线性外推)

```bash

python3 water_control_cli.py set-mm 80      # 等 10~15 分钟稳
python3 water_control_cli.py get-learn      # 记下 C
```

## 方式二:在线自学习([G12])

不想手测,或现场水量经常变化,可以让 PLC 自己学平衡线截距 C(和诊断量 d0)。**代码已内置,`bAutoLearn` 默认 TRUE**;手测方式(上面)仍然可用,两者共用同一组变量。

### 原理

两个量都是**直接可观测量**,不是模型推断:

| 量 | 什么时机可直接观测到 | 门控条件 | 用途 |
|---|---|---|---|
| **d0** | 阀全关(抽水=0)时,水位上涨速率就是 d0 | 阀开度 < 1% 且 速率 > 0.02 %/s | 诊断(看装水量/管路状态),预开律已不用它 |
| **C**(平衡线截距) | 稳态时 `C = 阀开度 + 液位%/rStatK`,与当前目标水位无关 | \|误差\| < 1%(≈1.3mm)且 \|速率\| < 0.05 %/s | 每拍派生 `u_eq(SP) = C − SP/rStatK` 供预开阀 |

**学 C 不学 u_eq** 是 2026-10-20 实测带来的修正:u_eq 随目标线性变化(100mm≈31%,130mm≈21%),学成一个全局常数在换目标后就偏了;C 才是同一装水量下的不变量,而它会随两桶水量分配整体平移(10-19 的 49.1 → 10-20 的 58.1)。

学习方法是一阶低通(指数滑动平均):

```
估计值 ← 估计值 + α × (观测量 − 估计值)      α = 周期/(时间常数+周期) ≈ 0.002
```

性质:永不跳变(单样本只影响 α 比例)、指数收敛(C 取 60s 时间常数:120s 后误差 ~14%,180s 后 ~5%)、工况变化自动跟随。

**不需要"学完才能用"**:估计值任何时候都可用,初始为默认值,过程中不断精化。

**自洽性**:预开阀一动作阀开度就 >1%,d0 学习自动停止——不会用被自己扰动过的数据学习;而预开阀生效时液位正是逼近 SP 的过程,稳态门控(|误差|<1% 且速率<0.05)满足后学到的正是"预开值 = 平衡开度"这一自证结果。

### 看学习结果

学习值实时映射到输入寄存器空闲槽(不需改 Machine Expert 数组大小):

| 寄存器 | 内容 |
|---|---|
| Device_0/1 | 学习到的 d0(%/s) |
| Device_6/7 | 派生的 u_eq(%),对应**当前目标** |

截距 C 本身不回读(没有空闲寄存器对),`get-learn` 用 `C = u_eq + 液位%/rStatK` 现算,并给出当前阀开度相对平衡开度是偏大还是偏小(即液位接下来会降还是会涨)。

```bash
python3 water_control_cli.py get-learn
```

**读数不变 ≠ 没在学**:EMA 收敛后单拍变化小于显示精度就是"已经学到位"。判断依据是它与默认值(58.0 / 0.30)有无偏离、以及是否落在实测阀指令的中间区间——2026-10-19 现场 `u_eq` 恒读 22.96% 即属已收敛,而 `d0` 从 0.28 一路学到 0.47 是在学的表现。

### 固化(可选)

满意后二选一:

- `bAutoLearn := FALSE` 冻结当前值(掉电仍回到默认值)
- 把 `get-learn` 读到的值写进 `st/PLC_PRG_improved.st` 的 `rUeqBase`(C)/ `rInflowRate`(d0)默认值 → 掉电也不丢

### 安全边界

- 估计值钳位:d0 ∈ [0.01, 5.0] %/s,C ∈ [0, 150] %(→ 派生 u_eq 再钳到 [0, rILimHi])
- 仅在自动模式、无传感器故障、液位在 HH/LL 之间时学习
- 学习值在 RAM,掉电/重新下载回到默认值
- 最坏情况:C 估偏 → 预开阀开大或开小,液位逼近的平衡点偏离 SP 约 `偏差×rStatK`%,但 PID 的积分项会把它拉回来(这正是积分该干的活),无安全风险;若估得离谱,水位转降判据(rRateFilt ≤ 0)立即退出预开

## 验证清单

1. **静态**:上电后 `status` 读数正常,`get-pid` 显示 PLC 在用的增益(bPidTune=OFF 时为 ST 默认值 2.0/0.10;在线写过 `set-pid` 则显示写入值且 tune: ON)。
