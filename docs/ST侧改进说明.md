## 现场观察记录

**2026-10-16**(G1~G8 版在跑,默认 Kp=1.8/Ki=0.30,bPidTune=OFF):设定 100mm,水位升到 ~110mm 泵才启动,抽到 ~95mm 才停,±10mm 极限环。诊断:积分振荡——下降段误差为负把积分拉深,回升段 P 项要先填平负积分坑才够 3% 开泵阈值;过冲段正积分又撑着阀关不掉。Ki=0.30 对慢积分对象过大,且旧 ±100 原始积分钳位使 I 项摆幅达 ±30% 阀开度。处置:[G9] 积分改贡献量限幅 + 默认 Ki 降至 0.10;临时在线缓解 `set-pid 2.0 0.10 0`;根因裁定仍靠 `step_test.py` 实测 K/τ。

另有细节:首周期(`bFirstScan`)用实测值初始化滤波器/斜坡/限速基准,避免上电从 0 拉起造成假误差冲击;手动模式下同步 `rPrevValve`/`rPrevLevel`,保证切回自动无扰。

**2026-10-19**(G1~G12 在跑,自学习 `bAutoLearn=TRUE`,Kp=2.0/Ki=0.10)

自学习回读(`output/get_learn.txt`):

- **d0 学习正常**:`0.2778 → 0.4605 → 0.4564 → 0.4766 → 0.4708 %/s`,即收敛到 **≈0.46~0.48 %/s**。过程可解释:`set-mm 50` 把阀拉满排水,再 `set-mm 100` 时液位远低于目标 → 阀饱和在 0 → 长时间"阀全关自由上涨"→ 门控打开,`rRateFilt` 稳定后就是真 d0。
- **u_eq 恒读 22.96%**:不是坏了。默认值 20.0 已被推到 22.96,正落在自动模式阀指令摆动的中间(现场 status 日志里阀 15.8~26.3%),即**已经收敛**;EMA 收敛后单拍变化 <0.005%,而旧版 `get-learn` 只显示两位小数,所以看起来"冻结"。现已把显示改到 4 位并顺手输出 `K = d0/u_eq`(本例 ≈0.0205 %/s per %阀)。

阶跃试验(`output/step_test_ABORTED_20261019_163025.csv`,77 行,中止):

- **中止原因**:u0 取的是自动模式的**瞬时**阀指令 33.51%,比真实平衡开度(≈23%)高约 10% → 整个基线在排水,液位从 103mm 一路掉到 73mm(-0.46 mm/s),阶跃 +10% 后 10 秒内跌到 43.49mm,触发 45mm 守卫 → 手动模式无 PLC 联锁,工具自守卫按设计动作,阀已回 u0、模式已还原。
- **抢救出的数据**(切线法):s0=−0.314 %/s,s1=−2.24 %/s,**K≈0.19 %/s per %阀,τ≈2.4 s**,外推 **d0≈+6.15 %/s**。
- **但这个 K 不能用**:外推 d0=6.15 与实测学到的 0.47 差 **13 倍**;而用学到的 d0/u_eq 反推的工作带增益 K≈0.021 能同时解释基线斜率(0.47−0.021×33.5≈−0.23,实测 −0.31)。也就是说 **阀从 33.5% 开大到 43.5% 后排水速率从 0.5 加速到 2.9 mm/s,这一段落在低液位(43~73mm)强非线性区**,斜率差被"液位自己也在跌"污染了。结论:本次只给出 τ 的量级(1~3 s,响应在阶跃后 1~2 s 内就跟上了,纯滞后确实很小),**K 必须在平衡点附近重测**——K 差 9 倍,SIMC 推荐增益就差 9 倍,不能据此加大 Kp/Ki。

工具改造(`step_test.py`,针对上面两个坑):

1. **u0 默认改取 PLC 学到的 u_eq**(与 `get-learn` 同一寄存器来源),读不到才退回当前阀指令;
2. 新增**调零探针**:切手动后先测 20s 斜率,若液位还在漂就按 `Δu = s/K_prior` 微调 u0(最多 3 次,单次 ≤15%),直到基线接近静止才开始记录——保证样本取自平衡点附近;
3. **记录时长按离守卫的液位余量自动截短**(余量 / 预估速率 × 0.8),不再固定 180s 把水箱排到底;
4. **中止/中断也用已采数据输出分析**,并对"基线漂移 >15mm""阶跃后漂移 >25mm""外推 d0 与学到的差 >2 倍"给出有效性警告;
5. `--record` 默认 120s,新增 `--probe` / `--no-trim`。

下一步:在 100mm 附近重跑 `python3 step_test.py`(现在会自动从 u_eq≈23% 起步并调零),取干净的 K 与 τ;`rPreOpenLead = 2τ`,标定完把 `bPreOpenEn` 置 TRUE。

### 与上位机斜坡的关系

CLI `set_water_level.py` 的斜坡(≤5mm/步、超前限幅 ±10mm)是主防线;PLC 内 SP 斜坡(G2)是第二道防线,覆盖 `set-mm`/`write`/HMI 直写等不经过脚本的路径。两者叠加不冲突——CLI 斜坡步进本身就慢于 G2 限速时,G2 不产生额外延迟。

## 增益裁定:阶跃试验(`step_test.py`)

两套文档增益(3.0/0.45 vs 1.8/0.30)矛盾且出处不可考,**以实测为准**。本对象是"积分过程 + 纯滞后",稳定边界约为 `Kp < 1.57/(K·τ)`——K(对象增益)和 τ(纯滞后)不实测,任何增益都只是猜测。

`skill/water-level-control/scripts/step_test.py` 用经典反应曲线法自动完成:

```bash
# 液位先调到试验窗口 (55-140mm, 建议 90-100mm), 然后:
python3 step_test.py                 # 默认: 阀+10%阶跃, 基线60s+记录180s
python3 step_test.py --step -10      # 液位偏高时用关小阀方向
```

流程:切手动→开泵→阀置 u0 记录基线斜率 s0→阶跃 Δu 记录 s1→恢复现场→输出:

- **K** = (s0−s1)/Δu(对象增益 %/s per %阀)、**τ**(切线法交点)、**d0**(阀全关时自然入流速率)
- **SIMC/IMC 推荐增益**:`Kp = 1/(K·(λ+τ))`,`Ti = 4(λ+τ)`,`Ki = Kp/Ti`,输出 λ=τ(标准)与 λ=2τ(鲁棒)两档
- 原始数据 CSV(时间/液位mm/液位%/阀开度/状态字),可复查拟合

拿到推荐值后的落地顺序:

1. `water_control_cli.py set-pid <Kp> <Ki> 0` 在线写入(bPidTune 路径,无需重新下载程序),`set_water_level.py` 设几个不同目标观察;
2. 确认稳定后回填三处:`st/PLC_PRG_improved.st` 声明区默认值(G1)、`set_water_level.py` 的 `SEGMENTS` 分段表(若分段差异确实存在,可在多个液位高度重复试验取点)、`SKILL.md` 文档;
3. 在 Machine Expert 中重新编译下载,使 bPidTune=0 时的默认值也是实测值。

**安全说明**:手动模式下 PLC 的 HH/LL 联锁被手动阀开度覆盖(ST 第 5 段在联锁之后执行),试验期间 PLC 不提供液位保护——工具自带守卫:液位越出 [45,150]mm、传感器故障或 Ctrl+C 均立即中止并把阀恢复到 u0、按试验前模式还原。

## 参数标定:预开阀三个数的量法

[G11] 上升预开阀需要三个实测值。**默认 `bPreOpenEn = FALSE`(不生效),标定完再置 TRUE**。

### 前提:左桶水位固定(重要,先做这一步)

d0 由左右桶水位差驱动(重力自流 `Q ∝ √Δh`),所以它随**左桶水位**变化:在左桶加水/放水后 d0 会明显改变(Δh 300→600mm 时 d0 约 ×1.41),此时 `rInflowRate` 和 `rUeqEst` 都必须重测。

**运行前提:保持左桶水位固定。** 做法二选一:

1. 左桶壁标一条水位线,每次运行前补齐到该线(闭式循环水量守恒,一次运行中左桶水位基本不动);
2. 左桶加固定高度溢流堰(多余水回流右桶)→ 恒压头,免维护。

**为什么这样就够**:左桶水位固定后,Δh 只剩右桶水位一个变量。右桶在 50~150mm 全量程变化时 Δh 相对变化约 ±10%(Δh≈300mm 时),开方后 **d0 全程只变 ±8~10%** —— 对预开阀时机判断足够(触发时刻误差约 10% 的 T_lead,可忽略)。u_eq = d0/K 同样稳定。

**复测规则**:改变左桶水位线 / 改动上管路(管径、长度、阀门)/ 换泵换阀 → 三个参数全部重测。

**注**:改设定值会把水在两桶间重新分配(右桶升 10mm,左桶约降 10 × 右桶截面积/左桶截面积 mm)。左桶远大于右桶时可忽略;两桶体积相近时要留意。

### ① d0 —— 自然上涨速率(%/s)

两种量法,任选:

**方法 A(推荐,顺带拿到 K 和 τ)**:跑阶跃试验,输出里直接有
`自然入流 d0: +x.xxxx %/s`。

**方法 B(直接测)**:让水位在阀全关状态下自然上涨,用 `trend` 读拟合斜率:

```bash
python3 water_control_cli.py manual        # 切手动(注意: 手动模式 PLC 联锁被手动值覆盖)
python3 water_control_cli.py pump off      # 停泵
python3 water_control_cli.py valve 0       # 阀全关
python3 water_control_cli.py trend --duration 180 --interval 5
# 读末行 "液位速率(拟合): +x.xxx mm/s (+x.xxxx %/s)" —— %/s 那个就是 d0
python3 water_control_cli.py auto          # 测完务必切回自动
```

注意事项:
- **起始水位要低**(建议 55~70mm),时长控制在 2~3 分钟——阀关着水位只涨不降,涨太快会顶到 140mm 以上。`trend` 是被动记录器,没有液位守卫,自己盯着点。
- 水位接近左桶水位(自流平衡点)时上涨会变慢,不要在那种状态测。
- 用 `--interval 5` 采样即可,斜率靠最小二乘拟合,不用密集采样。

### ② u_eq —— 平衡阀开度(%)

**在稳态下读阀指令的平均值**:

```bash
python3 water_control_cli.py auto
python3 water_control_cli.py set-mm 100
# 等 10~15 分钟基本稳定后:
python3 water_control_cli.py trend --duration 300 --interval 5
# 读末行 "阀指令: ... mean=xx.x%" —— 这个 mean 就是 u_eq
```

说明:理论上 u_eq 与目标水位无关(稳态抽水必须等于入流),所以**换一个目标值再测一次,两个 mean 应该接近**——这本身就是对系统特性的验证。若两次差异很大,说明有别的因素(左桶水位变化、阀非线性),把两个值都告诉我。

### ③ τ —— 纯滞后(s),以及 K

跑阶跃试验,读输出里的 `纯滞后 τ: xx.x s`。然后:

```
rPreOpenLead = 2 × τ      (保守可取 3τ; 想更快到位可取 1.5τ)
```

### 填参数并启用

在 `st/PLC_PRG_improved.st` 声明区把三个值改成实测值,并把 `bPreOpenEn := TRUE`:

```iecst
bPreOpenEn   : BOOL := TRUE;
rInflowRate  : REAL := <实测 d0>;      (* %/s *)
rUeqEst      : REAL := <实测 u_eq>;    (* % *)
rPreOpenLead : REAL := <2τ>;           (* s *)
```

编译下载后验证:把目标从低处调高(例如 60 → 100mm),观察水位接近目标时阀是否**提前**开始开、水位是否平顺收口而不是冲过去再回落。

## 方式二:在线自学习([G12])

不想手测 d0/u_eq,或现场水量经常变化,可以让 PLC 自己学。**代码已内置,`bAutoLearn` 默认 TRUE**;手测方式(上面)仍然可用,两者共用同一组变量。

### 原理

两个量都是**直接可观测量**,不是模型推断:

| 量 | 什么时机可直接观测到 | 门控条件 |
|---|---|---|
| **d0** | 阀全关(抽水=0)时,水位上涨速率就是 d0 | 阀开度 < 1% 且 速率 > 0.02 %/s |
| **u_eq** | 稳态(抽水=入流)时,阀开度就是平衡开度 | \|误差\| < 1%(≈1.3mm)且 \|速率\| < 0.05 %/s |

学习方法是一阶低通(指数滑动平均):

```
估计值 ← 估计值 + α × (观测量 − 估计值)      α = 周期/(时间常数+周期) ≈ 0.003
```

性质:永不跳变(单样本只影响 α 比例)、指数收敛(30s 时间常数:60s 后误差 ~14%,90s 后 ~5%)、工况变化自动跟随。

**不需要"学完才能用"**:估计值任何时候都可用,初始为默认值,过程中不断精化;而预开阀只在上涨最后 T_lead 才动作,那时已经学了 60~80s。

**自洽性**:预开阀一动作阀开度就 >1%,d0 学习自动停止——不会用被自己扰动过的数据学习。

学习值实时映射到输入寄存器空闲槽(不需改 Machine Expert 数组大小):

## Machine Expert 操作步骤

1. 打开工程,定位 `PLC_PRG`(ST 语言)。
2. 用 `st/PLC_PRG_improved.st` 的 `VAR...END_VAR` 替换声明区,其余替换实现区。
3. 确认 GVL 仍为:`rTargetLevel AT %MW0`、`rManualValve AT %MW2`、`rLevel AT %MW4`、`rValveCmd AT %MW6`(与提取到的现行 GVL 一致,无需改动)。
4. 编译(应 0 error;`qwModbusTCP_Server_Device_8.x` 位赋值写法保持原样)。
5. 任务配置不变:`T#100ms` 周期任务调用 `PLC_PRG`。
6. 登录 PLC → 下载 → **切换 RUN 前先把 bAuto 置手动**,观察一个周期无异常后切回自动。

## 验证清单

1. **静态**:上电后 `status` 读数正常,`get-pid` 显示 Kp=1.8/Ki=0.3(bPidTune=OFF 时)。
2. **斜坡生效**:CLI `write 80`(阶跃直写),观察 `rLevel` 与阀指令——阀应平滑变化(≤1%/周期),水位无过冲。
3. **抗超调**:`python3 set_water_level.py 120`,确认无冲过目标再回落的现象。
4. **去抖**:短暂短接/断开传感器信号 <1s,`bSensorFault` 不应置位;持续 >1s 应置位并联锁。
5. **联锁不降级**:强制 `rLevel≥95%`,阀应**立即** 100%(不受限速);强制 `≤5%`,立即停泵关阀。
6. **无扰切换**:手动给阀 50%,切自动,阀不应跳变。
