# ST 侧改进说明(optimize/level-control)

改进后的完整程序见 [`st/PLC_PRG_improved.st`](../st/PLC_PRG_improved.st),整段替换 Machine Expert 中 `PLC_PRG` 的声明区与实现区即可。**GVL 不变、Modbus 寄存器映射不变**,上位机 `water_control_cli.py` / `set_water_level.py` 无需修改即兼容。

## 问题定位(基于从 .project 提取的现行 ST 源码)

| # | 问题 | 后果 |
|---|---|---|
| P1 | 默认增益 `Kp=3.0, Ki=0.5`(bPidTune=0 时生效)。注意:文档中另有一套自称"现场验证"的 1.4~1.8/0.26~0.30,两套说法矛盾且均无实测记录佐证——**增益孰对孰错需用 `step_test.py` 实测裁定**(见下) | 若增益偏高:阀频繁大幅动作、振荡 |
| P2 | Modbus 写入的目标值直接作为 SP,无任何斜坡/滤波 | 阶跃 SP 在纯滞后 τ 内误差持续拉大 → 积分饱和 → 超调 |
| P3 | 微分对误差(`rError - rPrevError`),且 PV 无滤波 | SP 变化时微分踢;采样噪声被放大 |
| P4 | 抗饱和判别用**旧积分**算的 `rOut`,最终输出用**新积分**重算 | 判别与输出不一致,饱和边界附近积分仍会多累积一拍 |
| P5 | 传感器超限单周期即置 `bSensorFault` | 一次电磁干扰脉冲 → 误停泵关阀 + 报警抖动 |
| P6 | PID 输出无速率限制,单周期可 0→100% | 液压冲击、阀磨损、加剧振荡 |
| P7 | `rTargetLevel` 未钳位 | 上位机异常写入 >100% / 负值直接进 PID |

## 改进项(代码中 `[G1]`~`[G8]` 标注)

| # | 改进 | 参数(可在声明区调整) |
|---|---|---|
| G1 | 默认增益改为保守值(**临时**,待阶跃试验实测后回填,见下) | `Kp=2.0, Ki=0.10, Kd=0`(bPidTune=1 时仍由 Modbus 写入值覆盖) |

| G4 | **微分对测量**:SP 阶跃无微分踢,只响应水位实际变化 | — |
| G5 | 抗饱和一致性修复:饱和判别与最终输出用同一个更新后的 `rInt` | — |

| G7 | **阀输出速率限制**(仅 PID 路径;联锁/手动路径不限速,安全动作立即执行) | `rValveRate=10.0 %/s` |
| G8 | 目标水位钳位 0..100% | — |
| G9 | **积分状态改存"I 项输出贡献量(%阀开度)"**,限幅与 Ki 解耦。旧写法 `rInt` 钳位 ±100(原始 ∫e·dt),I 项范围 = Ki×100:Ki=0.30 时 I 项可摆 ±30% → 积分来回甩,2026-10-16 现场 ±10mm 振荡实锤;Ki 调小到 0.05 时 I 项又只有 ±5%,可能顶不住入流平衡点 → 静差消不掉。改存贡献量后,限幅单位就是阀开度 %,在线改 Ki 不再连带改积分能力 | `rILimHi=60.0 / rILimLo=-20.0`(%阀开度;上限须 ≥ 平衡入流所需开度,预估 20~40%,留裕量) |

## 现场观察记录

**2026-10-16**(G1~G8 版在跑,默认 Kp=1.8/Ki=0.30,bPidTune=OFF):设定 100mm,水位升到 ~110mm 泵才启动,抽到 ~95mm 才停,±10mm 极限环。诊断:积分振荡——下降段误差为负把积分拉深,回升段 P 项要先填平负积分坑才够 3% 开泵阈值;过冲段正积分又撑着阀关不掉。Ki=0.30 对慢积分对象过大,且旧 ±100 原始积分钳位使 I 项摆幅达 ±30% 阀开度。处置:[G9] 积分改贡献量限幅 + 默认 Ki 降至 0.10;临时在线缓解 `set-pid 2.0 0.10 0`;根因裁定仍靠 `step_test.py` 实测 K/τ。

另有细节:首周期(`bFirstScan`)用实测值初始化滤波器/斜坡/限速基准,避免上电从 0 拉起造成假误差冲击;手动模式下同步 `rPrevValve`/`rPrevLevel`,保证切回自动无扰。

### 与上位机斜坡的关系

CLI `set_water_level.py` 的斜坡(≤5mm/步、超前限幅 ±10mm)是主防线;PLC 内 SP 斜坡(G2)是第二道防线,覆盖 `set-mm`/`write`/HMI 直写等不经过脚本的路径。两者叠加不冲突——CLI 斜坡步进本身就慢于 G2 限速时,G2 不产生额外延迟。

## 增益裁定:阶跃试验(`step_test.py`)

两套文档增益(3.0/0.45 vs 1.8/0.30)矛盾且出处不可考,**以实测为准**。本对象是"积分过程 + 纯滞后",稳定边界约为 `Kp < 1.57/(K·τ)`——K(对象增益)和 τ(纯滞后)不实测,任何增益都只是猜测。

`skill/water-level-control/scripts/step_test.py` 用经典反应曲线法自动完成:

```bash
# 液位先调到试验窗口 (55-140mm, 建议 90-100mm), 然后:
python3 step_test.py                 # 默认: 阀+10%阶跃, 基线60s+记录180s
python3 step_test.py --step -10      # 液位偏高时用关小阀方向
```

流程:切手动→开泵→阀置 u0 记录基线斜率 s0→阶跃 Δu 记录 s1→恢复现场→输出:

- **K** = (s0−s1)/Δu(对象增益 %/s per %阀)、**τ**(切线法交点)、**d0**(阀全关时自然入流速率)
- **SIMC/IMC 推荐增益**:`Kp = 1/(K·(λ+τ))`,`Ti = 4(λ+τ)`,`Ki = Kp/Ti`,输出 λ=τ(标准)与 λ=2τ(鲁棒)两档
- 原始数据 CSV(时间/液位mm/液位%/阀开度/状态字),可复查拟合

拿到推荐值后的落地顺序:

1. `water_control_cli.py set-pid <Kp> <Ki> 0` 在线写入(bPidTune 路径,无需重新下载程序),`set_water_level.py` 设几个不同目标观察;
2. 确认稳定后回填三处:`st/PLC_PRG_improved.st` 声明区默认值(G1)、`set_water_level.py` 的 `SEGMENTS` 分段表(若分段差异确实存在,可在多个液位高度重复试验取点)、`SKILL.md` 文档;
3. 在 Machine Expert 中重新编译下载,使 bPidTune=0 时的默认值也是实测值。

**安全说明**:手动模式下 PLC 的 HH/LL 联锁被手动阀开度覆盖(ST 第 5 段在联锁之后执行),试验期间 PLC 不提供液位保护——工具自带守卫:液位越出 [45,150]mm、传感器故障或 Ctrl+C 均立即中止并把阀恢复到 u0、按试验前模式还原。

## Machine Expert 操作步骤

1. 打开工程,定位 `PLC_PRG`(ST 语言)。
2. 用 `st/PLC_PRG_improved.st` 的 `VAR...END_VAR` 替换声明区,其余替换实现区。
3. 确认 GVL 仍为:`rTargetLevel AT %MW0`、`rManualValve AT %MW2`、`rLevel AT %MW4`、`rValveCmd AT %MW6`(与提取到的现行 GVL 一致,无需改动)。
4. 编译(应 0 error;`qwModbusTCP_Server_Device_8.x` 位赋值写法保持原样)。
5. 任务配置不变:`T#100ms` 周期任务调用 `PLC_PRG`。
6. 登录 PLC → 下载 → **切换 RUN 前先把 bAuto 置手动**,观察一个周期无异常后切回自动。

## 验证清单

1. **静态**:上电后 `status` 读数正常,`get-pid` 显示 Kp=1.8/Ki=0.3(bPidTune=OFF 时)。
2. **斜坡生效**:CLI `write 80`(阶跃直写),观察 `rLevel` 与阀指令——阀应平滑变化(≤1%/周期),水位无过冲。
3. **抗超调**:`python3 set_water_level.py 120`,确认无冲过目标再回落的现象。
4. **去抖**:短暂短接/断开传感器信号 <1s,`bSensorFault` 不应置位;持续 >1s 应置位并联锁。
5. **联锁不降级**:强制 `rLevel≥95%`,阀应**立即** 100%(不受限速);强制 `≤5%`,立即停泵关阀。
6. **无扰切换**:手动给阀 50%,切自动,阀不应跳变。
