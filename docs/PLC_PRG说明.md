> 这里面向改程序的人。**不要把这些内容加回 SKILL.md** —— 它们会干扰 agent 的调用判断。

> 对应源文件：`st/PLC_PRG.st`（239 行，任务周期 20ms）。

## 1. 任务周期必须是 20ms

`tCycle : TIME := T#20MS` 要与 Machine Expert → Application → Task Configuration →
MAST → **Interval** 的实际值一致。

⚠️ 2026-10-27 之前所有版本都写着 `T#100MS` 而实际任务是 20ms，程序每 0.02s 执行一次
却按 0.1s 换算：

| 受影响的量 | 后果 |
|---|---|
| `rDeriv = Δ/0.1` | 速率系统性偏小 5 倍 → 速度阻尼只剩 1/5 |
| `rInt += e·rDt` | 积分快 5 倍 |
| 硬编码系数的两个 EMA | 时间常数只有设计值的 1/5 |

**`rDt` 在 watch 窗口里显示 0.1 不能作为任务周期的证据** —— 它是
`TIME_TO_REAL(T#100MS)/1000` 的常量除法，任务改成任何值它都显示 0.1。
确认方法只有两个：看 Task Configuration，或加扫描计数器经空闲寄存器读出。

日志验证（`output/plc_v5_running_log.txt` 与 2026-10-27 的 `set-mm 50` trend）：

- 阻尼弱 5 倍：run4 t=13，代码要求 −19.97pp，实测只贡献 ≈−4.5pp，比值 0.22 ≈ 1/5
- 积分快 5 倍：run5 `rInt` 在 2s 内从 0 到 −43（e≈−4.6）即 −19.6/s；
  100ms 预测 −4.6/s，20ms 预测 −23/s

### 连带教训：滤波系数不随 rDt 缩放

两个 EMA 的系数是硬编码的，所以改 `rDt` **不会**修正它们的时间常数。
2026-10-27 只改 `tCycle` 一个量的结果：阻尼恢复全额但作用在几乎没滤波的速率上，
阀指令 std 从正常值暴涨到 **7.73pp**（峰峰 33.8pp，在 20~85% 之间每秒乱跳）。

噪声传递模型与实测吻合：静水抖动 σ≈0.21% 经 [τ=67ms] → 差分/rDt → [τ=200ms] → ×6.24
⇒ 阻尼项 ±7.3pp(1σ)。还原到 τ=333ms/1s 后 ⇒ ±1.6pp。

**教训：`rDt` 与滤波系数共同决定速率信号的信噪比，不是独立变量，必须一起改。**

## 2. 执行顺序（每 20ms 一遍）

1. **传感器自检**：`iLevelRaw` 超出 `4000±200 / 20000±200` 即置 `bSensorFault`。
   ⚠️ **没有去抖** —— 单次尖峰就会触发。静水抖动实测 60~68 计数，±200 有余量，
   但没有连续计数保护。若要加，用 `iFaultCnt >= 10`（连续 200ms）这类判据，
   窗口不要再收窄（±50 会在量程两端频繁误报）。
2. **双滤波测速**（关键改进，不要退回"差分 + EMA"）：
   ```iecst
   rLevelFilt := 0.89 * rLevelFilt + 0.11 * GVL.rLevel;   (* 快滤波 τ ≈ 0.17s *)
   rLevelSlow := 0.97 * rLevelSlow + 0.03 * rLevelFilt;   (* 慢滤波 τ ≈ 0.65s *)
   rLevelRate := (rLevelFilt - rLevelSlow) / 0.49;        (* 0.49 ≈ τ慢 − τ快 *)
   ```
   两个一阶低通之差除以时间常数差 = 带内在平滑的速度估计，比"先微分再低通"干净得多。
   实测（蒙特卡洛，σ=0.15/0.21/0.30%）：`rLevelRate` 噪声 0.065/0.090/0.130 %/s，
   乘 `rVelDampGain=3.6` 后对阀指令只贡献 **±0.23/0.33/0.47pp**。
   滤波系数硬编码、**不随 `rDt` 缩放**，任务周期一改这两个 τ 就跟着变。
3. **联锁**（最高优先级，在 PID 之前）：
   传感器故障 → 阀 0 / 泵 OFF / `rInt := 0`；
   `rLevel ≥ 98.5%`(155.5mm) → 阀 100 / 泵 ON / `rInt := 0`；
   `rLevel ≤ 5%`(34.8mm) → 阀 0 / 泵 OFF / `rInt := 0`。
   ⚠️ `rLvlLL = 5%` = 34.8mm **在泵物理下限 45.3mm 之下**，永远不可能先于干抽触发。
4. **目标变更检测**：`|target − rPrevTarget| > 1%` 时 `rInt := 0`，并按误差符号锁存
   `bRisingTask`。
5. **分段前馈** `rUeqBase` + 上升回差补偿 → `rUeqDyn`（见第 3 节）。
6. **比例 + 速度阻尼**，系数按误差分段：
   ```iecst
   IF ABS(rError) <= 4.0 THEN   rPD := (rKp*1.15)*rError + (rVelDampGain*1.15)*rLevelRate;
   ELSE                         rPD := (rKp*0.90)*rError +       rVelDampGain *rLevelRate;
   END_IF
   ```
   Kp=2.0 / rVelDampGain=3.6 时即：近区 `2.30·e + 4.14·rate`，远区 `1.80·e + 3.60·rate`。
   **没有微分项** —— `rKd` 只被声明和钳位，从未进入 `rPD`；超前作用全部由速度阻尼提供。
   `rError := rLevelFilt − GVL.rTargetLevel`（用滤波值）。
7. **输出上下限**：`rMinOut := 12.0`、`rMaxOut := 75.0`；仅当 `rError > 8.0`
   （远高于目标、正在大幅下降）时 `rMinOut := LIMIT(12.0, rUeqDyn + 2.0, 75.0)`，
   用"比平衡开度高 2pp"的托底防止下降段失速。上升段与近目标区一律用物理下限 12%。
   下限 12% > `rPumpOnThr` 3% ⇒ **自动模式下泵永不停止**（省掉启泵延迟）。
8. **积分门控**（`rEffKi = rKi × 0.85 = 0.221`，限幅 `rInt ∈ [−80, +80]`
   ⇒ **积分权限 ±17.7pp**），按顺序判断：
   - `|e| > 8%` → `rInt := 0`（远距离不积分，交给前馈）
   - `|e| ≤ 1.1%` 且 `|rate| < 0.25 %/s` → 冻结（稳态靶心 ±1.4mm，保平直线）
   - `(e > 2 且 rate < −0.5)` 或 `(e < −2 且 rate > 0.5)` → 冻结（正在高速冲向目标，
     暂停同向积分防超调）
   - 未饱和输出顶到**物理**限 12/75% 且误差同号 → 冻结（抗饱和。比的是 12/75
     而不是动态 `rMinOut`，否则积分会被托底卡死）
   - 其余 → `rInt := rInt + rError·rDt`
9. **输出**：`rValveCmd := LIMIT(rMinOut, rUeqDyn + rPD + rEffKi·rInt, rMaxOut)`。
10. **泵迟滞**：3% 启 / 1% 停。
11. **手动模式**（在联锁段**之后**，因此会覆盖联锁）：阀 = `rManualValve`、
    泵 = `bManualPump`，反算 `rInt` 做无扰切换，并把两个滤波器复位到当前液位。

## 3. 平衡曲线

四点实测（50mm→46.2%、60mm→45.0%、100mm→32.5%、150mm→25.8%）拟合的分段线性，
段间连续：

| 目标 mm 区间 | 公式 | 端点值 |
|---|---|---|
| ≤ 65 | `46.2 − (mm − 50) × 0.120` | 50mm → 46.2%，65mm → 44.4% |
| 65 ~ 105 | `44.4 − (mm − 65) × 0.320` | 100mm → 33.2%（实测 32.5，残差 0.7pp），105mm → 31.6% |
| > 105 | `31.6 − (mm − 105) × 0.129` | 150mm → 25.8% |

**中段斜率（0.320 pp/mm）是两端的 2.5 倍** ⇒ 单一直线永远拟合不了全量程。
这是早先所有"一条直线"版本失败的根源之一。

上升任务（`bRisingTask = TRUE`）且目标在 75~135mm 时叠加三角形回差补偿：

```iecst
rUeqDyn := rUeqBase + 8.0 * (1.0 - ABS(rTargetMM - 100.0) / 40.0);
```

100mm 处最高 **+8.0pp**，75mm 与 135mm 处 +3.0pp，区间外为 0。

### 三个已知问题

1. **`bRisingTask` 到位后不复位**（只在目标变化 >1% 时更新）。所以"升到 100mm 后保持"
   与"降到 100mm 后保持"的 `rUeqDyn` 相差 8pp，差值由积分吸收（需 `rInt ≈ −36`，
   占 ±80 限幅的 45%）。液位最终一样，但**上升到达后收敛更慢**。
2. **PLC 侧另有一套 mm↔% 换算**：`rTargetMM = 28.31 + (rTargetLevel/100) × 129.14`
   （4mA→28.31mm、20mA→157.45mm、1% = 1.2914mm），与 CLI 的标定
   （31.34 / 159.08 / 1.2774）**差约 3mm**。四个实测点是按 PLC 那套换算记录的，
   所以 CLI 重新标定之后，分段常数必须按同一口径复核。
3. **闭式回路 ⇒ `u_eq` 取决于固定总水量在两桶之间怎么分。** 平台测量前必须把左桶
   补水到同一刻度。2026-10-26 实测：同一条"直线"在 35 分钟内移动了 ≥10pp。

## 4. Modbus 寄存器映射

PLC **不会**自动映射 `%MW`/`%M`，映射在 ST 里显式完成。
**数组下标 = Modbus 寄存器号**，不是 `%MW` 地址。REAL 占 2 个寄存器，低字在前
（现场验证：写入 10.0 得到 `[0, 16672]`）。

**保持寄存器**（`iwModbusTCP_Server_Device_N`，FC03 读 / FC16 写）：

| 下标 | `%MW` | 变量 |
|---|---|---|
| 0/1 | 0 | rTargetLevel |
| 2/3 | 20 | rKp |
| 4/5 | 22 | rKi |
| 6/7 | 2 | rManualValve |
| 10 | 102.0/106.0 | 控制字 bit0=bAuto, bit1=bManualPump, bit2=bPidTune |
| 12/13 | 24 | rKd（**控制律未使用**） |

**输入寄存器**（`qwModbusTCP_Server_Device_N`，FC04 只读）：

| 下标 | `%MW` | 变量 |
|---|---|---|
| 0/1 | 26 | `rRiseSpeedOffset` = 8.0（**控制律未使用**，仅保留供 CLI 监控） |
| 2/3 | 4 | rLevel |
| 4/5 | 6 | rValveCmd |
| 6/7 | 28 | `rUeqDyn`（PLC 当拍实际使用的前馈开度） |
| 8 | — | 打包状态字 bit0=bAuto,1=bPumpCmd,2=bSensorFault,3=bAlarm,4=bPump(%QX4.0) |
| 9 | — | iLevelRaw（4000..20000，量程校准用） |
| 10/11 | 20 | rKp 反馈 |
| 12/13 | 22 | rKi 反馈 |
| 14/15 | 24 | rKd 反馈 |

数组尺寸：保持 ≥ 0..13，输入 ≥ 0..15。

### CLI 的 `get-learn` 标签与当前程序不匹配

CLI 把输入寄存器 0/1 标为 **C**（平衡线截距）、6/7 标为 **u_eq**，并做一致性校验
`C = u_eq + SP/STAT_K`。这套标签是按已删除的 `PLC_PRG_simple`/`_v3` 设计的：

- **0/1 读到的是 `rRiseSpeedOffset` = 8.0**，控制律根本没用它。打印成 "C = 8.0"
  是误导，一致性校验也无意义。
- **6/7 读到的是 `rUeqDyn`，这个是有用的** —— `resume` 就是靠它预置积分。

`water_control_cli.py` 里的 `STAT_K = 2.13` 同样已过期。
彻底修好需要改 CLI（把 0/1 的标签改掉、去掉那行校验），目前只在 SKILL.md 里做了提示。

### 手动段的积分跟踪与自动段不自洽

```iecst
rInt := (GVL.rValveCmd - rUeqDyn - rKp * (GVL.rLevel - GVL.rTargetLevel)) / rKi;
```

它除以 `rKi`(0.26) 而自动段乘的是 `rEffKi = rKi × 0.85`(0.221)，且用 `rKp` 而不是
分段后的 `rKp × 1.15 / 0.90`。所以切回自动时阀会有约 **15% × (阀 − u_eq)** 的台阶
（手动阀比 u_eq 高 10pp 时掉 1.5pp）。量级不大但不严格无扰。
严格写法应是 `rInt := (rValveCmd − rUeqDyn − rPD) / rEffKi`。

## 5. 整定症状 → 对策

1. **缓慢的 ±5–10 mm 循环、阀指令跟着摆**：积分过强 —— 降 Ki（实际生效的是
   `Ki × 0.85`）。限幅是对 `rInt` 的，降 Ki 会同时缩小权限（`80 × Ki × 0.85`）。
2. **持续稳态静差、不振荡**：先分清是权限不足还是靶心冻结。
   权限 = `80 × rKi × 0.85`（Ki=0.26 时 ±17.7pp）。若 `get-learn` 读到的 `rUeqDyn`
   与稳态阀指令差得远，说明分段曲线在该目标处偏了、积分已顶到 ±80 ——
   **应该修曲线常数，不是加大 Ki**。±1.4mm 以内的残差是靶心休眠故意留的。
3. **阀频繁大幅跳变**：先确认 `rLevelRate` 量级（应 <1 %/s 级别）。明显偏大就查
   任务周期是否仍是 20ms、两个滤波系数是否被改过；再考虑降 `rVelDampGain`(3.6) 或 Kp。
4. **上升冲过目标**：查 `bRisingTask` 是否被正确锁存（只在目标变化 >1% 时更新），
   以及目标是否落在 75~135mm 的补偿区间内。区间外（如 50→60mm、→150mm）没有补偿。
5. **下降砸穿目标**：`rError > 8%` 时的托底是 `rUeqDyn + 2.0`。砸穿说明 +2pp 不够，
   或者 `rMaxOut = 75%` 让下降段一直全速。

## 8. PLC 侧准备清单（Machine Expert）

1. 以太网口启用 Modbus TCP 服务器，从站 ID = 1
2. 保持寄存器数组尺寸覆盖下标 0..13
3. 输入寄存器数组尺寸覆盖下标 0..15
4. ST 映射片段齐全（顶部 PID 之前读入、底部写出），增益声明 `AT %MW20/22/24`，
   已编译下载
5. `PLC_PRG` 在运行的任务里，**任务 Interval = 20ms**（与 `tCycle` 一致），PLC 在 RUN
