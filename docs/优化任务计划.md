### P0-b 校准机制(CLI,已完成)

模型:

```
mm = K · (iLevelRaw − 4000) + b
K = 0.0087683 mm/计数   由静水两点法实测,之后固定
b = 19.8 mm             随 K 一起由两点法确定,日常也可单点修正
```

**首选流程:静水两点法(无泵、无入流、无扰动)**

条件:泵 OFF、阀 ≈0、左侧不向右侧自流(关阀/排空左桶),右侧由人工加水。

```bash
# 低水位(建议 ~60mm), 尺子量好后:
python3 water_control_cli.py calibrate --sample --label low
#   输出 raw 中位数, 并校验"泵 OFF 且阀 ≈0"; 不是静水态会拒绝
# 加水到高水位(建议 ~140mm), 再量:
python3 water_control_cli.py calibrate --sample --label high
# 两个数都记下后一次算出 K 和 b:
python3 water_control_cli.py calibrate --two-point <low_raw> 60.5 <high_raw> 139.8
```

为什么这样最准:没有流动就没有液面波动,压力探头读的是纯静态液位;人工加水也让
"实际水位"可以随时用尺子核对。两点跨度建议 60mm 以上,并让两点**把 50–150mm
工作区间夹住**——两点太近会把斜率的误差放大。

| 命令 | 用途 |
|---|---|
| `calibrate --sample --label <名称>` | 静水采样:校验泵/阀状态,连读 5 次取中位数,给出可复制的 raw |
| `calibrate --two-point RAW1 MM1 RAW2 MM2` | 由两点算 K 和 b 并写入 |
| `calibrate --show` | 打印当前 K/b 与换算表 |
| `calibrate --actual <mm>` | 单点:只改 b(日常零点漂移时用) |
| `calibrate --actual <mm> --check` | 只报误差,不写 |

内置拦截:

| 条件 | 动作 |
|---|---|
| 采样时泵在转或阀开度 >1% | 拒绝(`--force` 可绕) |
| 两点的 raw 差 <1000 计数,或实测水位差 <20mm | 拒绝(斜率不可辨) |
| 新 K 与原值差 >30% | 拒绝,需 `--force`(首次用两点法重建旧表时加) |
| 单点:3 次采样抖动 > 3mm | 拒绝(水位没稳) |
| 单点:显示值不在 50–150mm | 拒绝 |
| 单点:\|Δb\| > 40mm / > 25mm | 拒绝 / 需 `--force` |

配置落点:`~/.water-control/config.json` 的 `level_model`,并保留最近 20 次校准历史
`level_cal_history`(可观察 b 的长期漂移——漂得快说明探头在劣化)。

> 注意:重新标定 mm 换算**不会**影响 FOPDT 模型参数(K=2.13 %液位/%阀、τp、θ)——
> 那些是百分比尺度上的量,与 mm 标定无关。

- 若"太慢到不了位",缺的是 P2 的前馈,**不要靠提 Kp 换速度**

### 2026-10-21 现场结果:发现积分分离把控制打死

`trend_20261021_155148.csv`(118s,60 点)+ 调试日志:

| 时刻 | 液位% | 阀% | 误差 | 0.88×误差 |
|---|---|---|---|---|
| t=0 | 75.2 | 18.9 | 21.4 | **18.83** |
| t=118 | 80.8 | 23.8 | 27.0 | **23.76** |

阀开度**精确等于纯比例项**,118 秒里积分贡献恒为 0。根因是 `PLC_PRG_Current.st` 的
积分分离:

```iecst
IF ABS(rError) > 15.0 THEN rITerm := 0.0;   (* 误差 21~27% > 15% → 反复清零 *)
```

后果是纯 P 对峙,稳态点解出来是

```
0.88·(PV−SP) = C − PV/2.13   →   PV = (C + Kp·SP)/(Kp + 1/|K|) ≈ 81% ≈ 135mm
```

**液位永远停在 135mm,到不了 100mm**(实测上升速率已衰减到 +0.02%/s,正在逼近该点)。

⚠️ 教训:**积分分离对自衡对象是错的**,而且"冻结"和"清零"一样致命 ——
纯 P 必有静差(= 所需平衡开度 / Kp),带宽设成 5% 只会把卡死点从 135mm 换个算法再算一遍,
误差 27% 仍然远在带宽外,积分照样不动。正确做法是让积分在全误差范围内工作,
抗饱和交给"输出顶到 0/100% 且误差同号时冻结累加"(那已覆盖真正会 windup 的两种情形)。

## P2 控制律重写:前馈 + PI(`st/PLC_PRG_simple.st`,已完成)

旧版堆了太多概念(预开阀/到达时间/提前量、速率估计、微分、积分分离清零、d0 学习),
2026-10-21 重写为一套只有三条式子的控制律:

```
u_eq = C − SP/|K|                      前馈: 目标对应的平衡开度
u    = u_eq + Kp·e + I                 e = PV − SP(斜坡后)
I   += Ki·e·dt                         |e| ≤ 5% 且未饱和时累加, 限幅 ±15pp
```

**为什么上升/下降都不超调(结构保证,不靠调参)**

- 对象自衡 ⇒ 存在一个开度让液位恰好停在目标上。把阀开到 `u_eq(SP)`,液位按一阶
  曲线单调逼近并自行减速 —— **刹车由对象提供,与纯滞后 θ 无关**。
- 积分不再承担"从 0 爬到 27%"的任务,只修 `u_eq` 的模型误差(±15pp 限幅),
  因此大行程不会 windup,到位也不慢。
- PI 部分的闭环阻尼比 `ζ = (1+|K|Kp)/(2τp·ωn) = 1.05 > 1`(过阻尼),
  `ωn = √(|K|Ki/τp) = 0.073 rad/s`,`ωn·θ = 0.37` 属小滞后 → 下降方向不超调。
- SP 斜坡(2%/s)让上升变成"液位跟着目标爬",误差始终很小,前馈连续变化。

**删掉的概念**:上升预开阀 / `rTArrive` / `rPreOpenLead` / `rInflowRate`(d0)、
速率估计 `rRateFilt`、微分项、积分分离清零。
**保留**:PV 低通(1s)、SP 斜坡、阀速率限制(10%/s)、传感器故障去抖、HH/LL 联锁、
泵启停迟滞、C 的在线学习(EMA 300s)。
**安全修复**:联锁改到手动段**之后**执行,传感器故障与 HH 在任何模式下都不可被手动覆盖
(LL 仍只在自动生效,阶跃试验需要在低液位强制开泵)。

| `rKp / rKi / rKd` | 0.88 / 0.047 / 0 | SIMC λ=θ;Kd 不使用 |

### 未解决:32s 周期扰动

前馈+PI **不解决**这个 —— 它是对象侧的周期扰动(开环幅度约 ±10mm),
PID 只能压制。2026-10-21 的证据:Kp 从 0.88 降到 0.44,液位带从 12.5mm **涨到** 16mm
(+28%),与 `幅值 ∝ 1/(1+|L|)` 的预测(+25%)吻合 —— 自激振荡不可能因降增益而变大。
待做的判别实验见 P3。


物理事实:阀关着时液位平衡点在 C×K ≈ 124%(超量程),自流上升自己不会停在目标上;
控制器只有在冲过目标后才有动作,而 θ=5s + 阀 10%/s 限速意味着必然越过 5~8mm。
**唯一结构性解法是预开阀**:低于目标且上涨时把阀开到"目标对应的平衡开度",
平衡点即目标,液位一阶逼近并自行减速。

要改三处:

1. `u_eq` 改随目标派生:`rUeqEst = C − SP/rStatK`(rStatK=2.13);**[G12] 学 C(截距),不学 u_eq**
   原因:u_eq 随目标线性变化(100mm≈31%,130mm≈21%),学成常数换目标就偏 ~10% 阀开度
2. **退出条件**:现在写的是"误差<0 且 速率>0",逼近目标时速率天然趋零,会在还没到目标时
   交回 PID,而 PID 的 P 项会关小阀 → 平衡点上移 → 反而超调。
   改为"**液位到达目标(误差 > −0.5%)才交回**",速率仅作异常保护(低于目标却在下落 = u_eq 估大)
3. **修 `rITerm := rPreOpen` → `rPreOpen − rPD`**:否则退出那拍输出台阶式跳掉 |rPD|

### 能做到什么程度

上限由 C 的估计精度决定,残差 ≈ ΔC × 2.13。C 学到 1% 内 → 超调 **2~3mm**;
想进 ±2mm 需 C 稳定在 0.5% 内。做不到绝对零,但比现在的 5~8mm 好一个量级。

## v2 (`PLC_PRG_simple.st`) 的失败机理 —— 上升下降都超调的同一个根因

PI 跟随斜坡的稳态误差 = `v/(|K|·Ki)`。`rSpRate = 2%/s` ⇒ **e_ss = 20%**, 而对象最快只能以
~0.2%/s 跟随。SP 一路狂奔, 误差长期停在 10~22%:

| t | SP_ramp | PV | e | u = u_eq + 0.88·e |
|---|---|---|---|---|
| 0s | 55 | 55 | 0 | 26.6% |
| 5s | 65 | 55 | −10 | 13.1% |
| 10s | 75 | 58 | −17 | 2.2% |
| 15s | 85 | 63 | −22 | **0%(钳位)** |

比例项指挥的平衡液位是 `h* = SP + |K|·Kp·|e|`, e=−20% 时 `h* = SP + 37.5%`(48mm)
—— **上升段 P 项是油门不是刹车**。到达目标时上升速率 ~1.05%/s, 加上 θ=5s,
必然超调 ~10mm(实测 12.5mm 带, 量级吻合)。

下降方向是镜像: e=+20% ⇒ u ≈ 44% ⇒ 平衡液位 18%(58mm), 目标 70mm 被抽过 12mm,
然后阀关到 0 只能等自流回涨(τp=18.6s) ⇒ "抽过目标位且不能回调"。

附带伤害: `rTrimBand=5%` 使 |e|>5% 时积分**整段冻结**, 每次移动积分都不参与。

**根因: SP 斜坡速率比对象可跟随速率快 10 倍。是结构问题, 不是 Kp/Ki 数值问题。**

## v3 (`PLC_PRG_v3.st`) 的改动

三处, 不引入任何新概念:

| # | 改动 | v2 → v3 |
|---|---|---|
| ① | SP 斜坡速率 | `rSpRate` 2.0 → **0.25 %/s** |
| ② | 积分增益 | `rKi` 0.047 → **0.070** (Ti = 12.6s) |
| ③ | 积分分离带宽 | `rTrimBand` 5% → **删除** (限速斜坡已把 e_ss 定在 1.7%, 不需要) |

`bFfEn := FALSE` —— 前馈默认关闭, `u_eq = C − SP/|K|` 仍每拍计算并经寄存器 0/1、
6/7 报出(C 学习器只观测不参与控制)。Modbus 映射、GVL、寄存器地址与 v2 完全一致,
CLI 与 step_test 不需改动。

### 斜坡速率怎么定(三个上界, ①② 不需要对象模型)

```
① 超调      ≈ rSpRate × θ           纯滞后 θ 内刹不住的距离
② 平衡点偏移 = rSpRate × Ti          Ti = Kp/Ki
③ 跟随误差   e_ss = rSpRate / (|K|·Ki)   必须小到留在小信号线性区
```

**① 用现场数据验证过**: v2 的 `rSpRate=2%/s`、θ=5s → 预测超调 `2×5 = 10% = 12.8mm`,
**实测带宽 12.5mm**。Kp 从 0.88 改到 0.44 几乎不影响这个数 —— 超调由斜坡速率与
纯滞后决定, 不由增益决定。**这就是"调 Kp 没用"的原因。**

**② 的推导**: `Δh* = |K|·Kp·e_ss = |K|·Kp·v/(|K|·Ki) = Kp·v/Ki = v·Ti`。
`|K|` 被约掉了 —— **对象增益估错也不影响这个上界**, 模型无关。

取 `rSpRate = 0.25%/s`, `Kp/Ki = 0.88/0.070`:

| 量 | 值 | 判据 |
|---|---|---|
| 超调 | 0.25×5 = 1.25% ≈ **1.6mm** | ① |
| 平衡点偏移 | 0.25×12.6 = 3.1% ≈ 4.0mm | ② 最坏瞄准点, 非实际超调 |
| 跟随误差 e_ss | 0.25/0.149 = **1.7%** | ③ < 2% ⇒ 全程线性区 |
| ζ / ωn·θ | 0.86 / 0.45 | |
| 30% 行程耗时 | **120s** | |

要更快就提 `rSpRate`, 超调按 ① 线性放大: 0.5%/s → 3.2mm, 0.1%/s → 0.6mm。
**`rSpRate` 是唯一的"速度 vs 超调"旋钮, 且线性可预测。**

### 已撤回: 误差限幅式 SP 跟随(gap governor)

v3 第一版用 `SP_ramp ≤ PV + gap` 把误差钉死。这是错的:

- 被钉住的误差会被积分**持续累加**: `I` 以 `Ki·gap = 0.094pp/s` 单调漂移,
  100s 行程漂掉 9.4pp, 而上升 30% 只需要 `I` 变化 14pp。挡住"大误差"却制造了
  "持续小误差", 后者对积分的伤害是累积的。
- 冷启动更糟: `rITerm=0` 且前馈关闭时阀全关, 液位以最大自流速率上涨,
  积分要 4~5 分钟才爬到 27%, 这段路上没有任何东西在刹车。

纯限速斜坡没有这个问题: `e_ss` 恰好是让积分以"所需速率"移动的那个值
(`dI/dt = Ki·e_ss = v/|K| = −du_eq/dt`), 自洽, 不累积。

冷启动仍需注意 —— 下载后第一次进自动, `rITerm = 0`。用 `resume` 而不是 `auto`
(见下节), 它会把积分预置到 u_eq。

## CLI 新增: `stop` / `resume`(静水态)

`stop` = 关泵 + 阀 0% + 切手动, 上方左右桶连通由现场人工阻断, 然后**回读验证液位真的不动**。

写入顺序有讲究: `rManualValve=0` → `bManualPump=0` → **最后**才清 `bAuto`。
手动段的阀指令**没有速率限制**(`rValveRate` 只作用于自动路径), 先切手动会让阀
一步跳到 `rManualValve` 的旧值。

| 回读结果 | 含义 |
|---|---|
| 阀≈0、泵 OFF、漂移 <1mm | ✅ 已静止, 可校准/量尺 |
| 阀 >1% 或泵 ON 且 `bAlarm` | **HH 联锁在覆盖手动**(设计行为), 先把液位降到 HH 以下 |
| 阀≈0、泵 OFF 但漂移 >1mm | **上方连通没阻断**, 或桶体/管路漏水 |

未验证静止时退出码 = 2(`--force` 可绕)。`--settle N` 调漂移检查时长(默认 5s/5 次)。

`resume` **不等于** `auto`: 自衡对象需要 ~27% 开度才能持平, 而小误差下积分只能以
`Ki·|e| ≈ 0.1pp/s` 累加, 从 0 爬到 27pp 要 4~5 分钟, 这期间阀接近全关、液位一路涨过
目标。`resume` 先把 `rManualValve` 写成 PLC 报出的 `u_eq`(输入寄存器 6/7), 等一个周期
让手动段把 `rITerm` 跟踪过去, 再置 `bAuto`。`--valve <开度>` 可手动指定预置值。

用途: `calibrate --sample/--two-point` 之前、任何尺子量测之前、开环扰动试验、探头检查。
`calibrate --sample` 的拒绝信息已改为提示先跑 `stop`。

## 未测过的物理因素(14 项里只测过 5 项)

| 因素 | 为什么致命 |
|---|---|
| **抽出的水排到哪里**(回左桶 vs 排走) | 回左桶 = 水量守恒、C 稳定; 排走 = 左桶越抽越空、C 单调下降, 前馈注定追不上 |
| **阀的死区 / 摩擦滞环** | 死区 ≥3pp 时 Kp=0.88 下误差要到 3.4% 阀才动 → 回路变继电器 → 必然极限环。降 Kp 只会更糟 |
| 左桶水头 `H_左` 是否恒定 | `Q_in ∝ √(H_左 − h)`, 决定自衡强度与 C |
| 进水管是否气堵/段塞流 | 32s 周期扰动的头号嫌疑 |
| 进水管口在水面上还是水面下 | 水面上 → 卷气溅浪, 压力探头读到气泡 |
| 小开度下泵能否出水 | 决定阀的有效下限 |
| 液面晃动 vs 真实水量变化 | 探头只读它正上方那一小块 |

## 判别实验(下载 v3 之前做, 共 ~25 分钟)

**T1 · 自流能力(2min)** —— `manual` + `pump off` + `write 0` + `trend 180s`,
在 h≈60mm 与 h≈120mm 各一次。
不涨 ⇒ 左桶空/管堵, **不是控制问题**; 一阵一阵涨 ⇒ 气堵段塞流, 32s 的嫌疑犯。

**T2 · 阀死区(5min)** —— `manual` + `pump on`, 阀 20 → 22 → 24 → 22%, 每步等 45~60s
记液位方向。最小能引起反向的 Δu = 死区。≥3pp ⇒ Kp 必须重定, 或走机械路线。

**T3 · 平衡线复核(15min, 替代零冗余的 2 点)** —— 手动固定阀在 **4 个**开度
(15/22/29/36%), 每个等到连续 60s 变化 <0.02%/s 再记 (u, h)。
4 点拟合残差 <2% ⇒ 线性成立可开 `bFfEn`; 明显弯曲 ⇒ `|K|` 分段, 前馈不能用常数 K。
**同时看 4 点解出的 C 与 58/52.4 是否一致 —— 这是判断 C 稳不稳的唯一办法。**

**T4 · 32s 归因(顺手)** —— Kp=0.44 与 1.76 各跑 5min trend, **只看周期**。
周期不变 ⇒ 外部扰动; 周期随 Kp 变 ⇒ 极限环(多半是 T2 的死区)。

**(2) 对象在 300s 内非定常。** 阀恒定 24.46% 而液位 112.0 → 95.8(t=85) →

- 它对这条日志毫无影响(新下限 24.92% vs 旧 24.46%), 只改积分预置值, 只在到达目标后起作用

  没进 ±5% 的 P 带也没到稳态, 既未证实也未证伪
- 即使改对, 一小时后又错。**用一条会漂 10pp 的直线做前馈等于没有前馈**

### 由此得出的可证伪预测(改代码之前先验)

"能到稳定的水位"其实是稳定在低 5mm 处。若实测确实在 115 附近 ⇒ 分析成立, 按下面改;
若在 120 ⇒ 拟合错, 不要改任何数。

### 修改: 两个常数必须一起改

```iecst
rUeqDyn := 53.56 - 0.2295 * rTargetMM;     (* 原 59.33 - 0.207 *)
rRiseSpeedOffset := 1.0;                    (* 原 10.0 *)
```

offset 由 10 降到 1.07 是为了让上升段阀下限保持 **20.35% 不变**
(`21.43 − 1.07 = 20.36`), 即**上升行为一丝不动**, 只有积分预置值被修正 ⇒ 5mm 稳态偏差消失。

| 只改一个 | 后果 |
|---|---|
| 只改截距(offset 留 10) | 下限 11.43% → 平衡液位 **183.6mm** → 冲过目标 44mm |
| 只改 offset(截距留 59.33) | 下限 29.35% → 平衡液位 **105.5mm** → 永远到不了 140mm, **死锁** |

这也解释了刹车带改动为什么是灾难: 把下限从 20.35% 抬向 30.35%, 等于走了"只改 offset"那条路。

### 两个限制

1. **这条线只在 122~147mm 内验证过。** 局部斜率在变: 26→23% 段 2.85 mm/pp,
   23→20% 段 5.57 mm/pp。往低处外推 `|du/dh|` 更大 ⇒ 直线在 122mm 以下会**低估**
   所需开度 → 抽得过多 → 液位停在目标下方。要用到 100mm 必须再补低处平台(阀 28%/32%)。
2. **log1 直接与拟合线矛盾**: 线说 30% 的平衡液位是 102.7mm, 而 log1 恰好从 102.5mm
   起步, 前 45s 平着, 然后一路涨到 118.1 还在涨 —— **起点就在平衡点上却离开了**,
   说明那 300s 内入流在变大(非稳态)。而它是唯一低于 122mm 的数据 ⇒
   **目前没有任何 122mm 以下的可靠平衡数据。**

### CLI: `calibrate --three-point`(取代两点法)

`--two-point` 是 2 点解 2 未知数, 残差恒为 0, 量错一点/水面没静/探头非线性全都静默通过
—— 这正是本项目反复踩的"零冗余"坑。新增 `--three-point RAW1 MM1 RAW2 MM2 RAW3 MM3`:

- 最小二乘拟合, **逐点打印残差**, 任一点 >1.5mm(静水噪声底 0.4~0.5mm 的 3 倍)直接拒写并点名
- 跨度守卫: raw 跨度 ≥4000 计数、mm 跨度 ≥50mm、mm 必须随 raw 递增
- 分布守卫: 相邻间距悬殊(<0.25×)时警告"靠得近的两点决定不了斜率"
- 保留 K 比值 [0.7,1.3] 与 |Δb| >40 拒 / >25 需 `--force` 的原有守卫

## 2026-10-27 根因确认: 任务周期是 20ms, 而所有 ST 都写死 T#100MS

Machine Expert → Task Configuration → MAST → **Interval = 20ms**。
而 `tCycle : TIME := T#100MS` ⇒ `rDt = 0.1`, 程序却每 0.02s 执行一次。
**仓库里 7 个 ST 文件全部写死 T#100MS** —— 本项目从头到尾每个版本都带这 5 倍误差。

⚠️ `rDt` 在 watch 窗口里显示 0.1 **不能**作为任务周期的证据: 它是
`TIME_TO_REAL(T#100MS)/1000` 的常量除法, 任务改成任何值它都显示 0.1。

### v5 里受影响的四项

| 代码 | 设计意图(100ms) | 实际(20ms) | 后果 |
|---|---|---|---|
| `rDeriv := (rLevelFilt − rPrevLevel)/rDt` | 真实速率 %/s | **÷5** | 速度阻尼只剩 1/5 |
| `rInt := rInt + rError*rDt` | 每秒 +e×1.0 | **每秒 +e×5.0** | 积分快 5 倍 |
| `rLevelFilt := 0.7·filt + 0.3·level` | τ=333ms | **τ=67ms** | PV 平滑弱 5 倍 |
| `rLevelRate := 0.90·rate + 0.10·deriv` | τ=1s | **τ=200ms** | 速率平滑弱 5 倍 |

**净效果: 积分强 5 倍、阻尼弱 5 倍 —— 与设计意图正好相反。**
前两项都用日志验证过: run4 t=13 阻尼应 −19.97pp 实际 ≈−4.5pp(比值 0.22);
run5 的 rInt 在 2s 内 0→−43(e≈−4.6) 即 −19.6/s, 20ms 预测 −23/s、100ms 预测 −4.6/s。

### 撤回: "25s 振荡是外部扰动 / 阀死区极限环"

用真实生效的 `Ki_eff = 0.070×5 = 0.35`、10-26 平台的 `|K| ≈ 3.4`、τp ≈ 15s:

```
ωn = √(3.4×0.35/15)          = 0.282 rad/s
ζ  = (1+3.4×0.88)/(2×15×0.282) = 0.47      ← 欠阻尼
ωd = 0.282×√(1−0.47²)        = 0.248 rad/s → 周期 25.3s   (实测 25s)
```

**不需要外部扰动也不需要阀死区, 回路自己就在 25s 上欠阻尼振荡, 因为 Ki 偷偷大了 5 倍。**
(τp≈15s 是为对上而反解的, 所以这是一致性检验而非独立预测。)

⇒ **本项目推荐过的每一个 Ki(0.047 / 0.070 / 0.235…)在运行的 PLC 里都是标称值的 5 倍**,
所有 SIMC 整定、λ 档、ζ=1.05 的推导输入全是错的。P3 的"机械/外部扰动"排查、
T2 的阀死区测试、T4 的周期归因, 优先级全部下调。

## 2026-10-27 第二轮: 滤波系数与积分权限(同一根因的连带项)

`Interval = 20ms` 确认后, 只改 `tCycle` 会让阀指令剧烈抖动(实测 std 7.73pp、峰峰 33.8pp、
在 20~85% 之间每秒乱跳)。**原因: 两个 EMA 的系数是硬编码的, 不受 rDt 影响**, 所以在 20ms
任务下它们的时间常数一直只有设计值的 1/5:

| 滤波 | 设计(100ms) | 20ms 实际 |
|---|---|---|
| `rLevelFilt := 0.7·+0.3·` | τ=333ms | τ=67ms |
| `rLevelRate := 0.90·+0.10·` | τ=1s | τ=200ms |

改 `rDt` **之前**, `rDeriv = Δ/0.1` 把速率压小 5 倍, 这个错误恰好在压制噪声 —— 两个 bug
互相抵消了一部分。只修一个就暴露了另一个。

**噪声传递模型(与实测吻合)**: 静水抖动 σ≈0.21% 经 [τ=67ms] → 差分/rDt → [τ=200ms] → ×6.24
⇒ 阻尼项 ±7.3pp(1σ); **实测阀指令 std = 7.73pp**。还原到 τ=333ms/1s 后 ⇒ ±1.6pp, 抑制 4.6 倍。

⚠️ 教训: "一次只改一个变量" 在这里是错的 —— `rDt` 与两个滤波系数**共同决定速率信号的信噪比**,
不是独立变量, 必须一起改。

### 已改(与 `PLC_RPG_v5.bak` 的全部代码差异, 11 行)

```diff
-tCycle : TIME := T#100MS;                              +tCycle : TIME := T#20MS;
+rTcFilt : REAL := 0.333;   +rTcRate : REAL := 1.0;     (* 时间常数, 秒 *)
+rAlphaF/rAlphaR : REAL;    +rIntLim := 250.0;  +rIntBand := 12.0;
+rAlphaF := rDt/(rTcFilt+rDt);   -rLevelFilt := 0.7*..+0.3*..
                                 +rLevelFilt := rLevelFilt + rAlphaF*(GVL.rLevel-rLevelFilt);
+rAlphaR := rDt/(rTcRate+rDt);   -rLevelRate := 0.90*..+0.10*..
                                 +rLevelRate := rLevelRate + rAlphaR*(rDeriv-rLevelRate);
-IF ABS(rError) <= 6.0       +IF ABS(rError) <= rIntBand
-rInt := LIMIT(-60.0, rInt, 60.0);   ×2 处   +rInt := LIMIT(-rIntLim, rInt, rIntLim);
```

α 由 `rDt` 算出 ⇒ 任务周期再变也不会重演。手动段的限幅必须用同一个 `rIntLim`,
否则手动切自动会丢修正量。

### 积分权限与积分门必须一起改(否则改了等于没改)

平直段 59 点: **液位 44.23mm / 阀 36.19% 是真实平衡点**, 而代码的线算出 46.57% ⇒
`rUeqDyn` 在低水位段偏高 **10.4pp**(比 10-26 平台在 122~147mm 段的 6~8pp 更糟)。

积分权限 = 限幅 × rEffKi = 限幅 × 0.0572 ⇒ ±60 只有 **±3.43pp**, 覆盖不了 10.4pp。
set-mm 50 的账: P 项 −5.84pp + 顶死的积分 −3.43pp = −9.27pp, 需要 −10.5pp,
差的 1.2pp 由"液位停在低处"吸收 ⇒ 实测静差 **−5.77mm**。

**但只放宽限幅不够**: 门外 `rInt` 被硬清零, 所以要先解"积分=0 时液位停在哪":

```
阀 = u_eq_cmd + 1.4e  与  真实平衡开度  相交  ->  停在目标下方 8.17mm, |e| = 6.33%
```

**6.33% 恰好在原来的 ±6% 门外** ⇒ 积分永不启动。现在液位能停在 44.23mm(门内)
只是因为阀在 ±7.7pp 乱跳把它晃进了门里; **滤波修好后抖动降到 ±1.7pp, 静差会从
−5.77mm 恶化到 −8.17mm。** 门宽必须 > P-only 对峙误差 ≈ 0.92×线误差(pp)。

收敛仿真(τp 取 15/30/60s 均同, 结果对 τp 不敏感):

| 目标 | 限幅/门 | 终值 | 静差 | 进入±2mm | 进入±0.5mm | 终态 rInt |
|---|---|---|---|---|---|---|
| 50 / 120 / 150mm | 旧 ±60 / ±6% | 目标−8.17mm | **−8.17mm** | 未 | 未 | 0(卡在门外) |
| 50 / 120 / 150mm | 新 ±250 / ±12% | 目标 | **0.00mm** | 39s | 71s | −182 |

±250 给出 ±14.3pp 权限, 需要的 rInt ≈ −183 在限幅内。

⚠️ 副作用(需实测确认): 门从 6% 放宽到 12% 后, 上升逼近段积分有更多时间往负方向累加
(约 −1.3pp), 会让阀更低一点、上升更快一点 ⇒ **上升超调可能略增**。若变差, 把
`rIntBand` 降到 9%(仍 > 6.33% 的对峙点), 不要动 `rIntLim`。
